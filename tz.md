необходимо разработать приложение, реализующие следующие задачи:
- формирование журнала сессий openvpn со следующими атрибутами:
  - учетная запись (аккаунтом считается CN сертификата)
  - время начала и окончания сессии
  - IP адрес с которого было произведено подключение, с привязкой к геолокации (страна/город)
  - неудачные попытки подключения (любая неудачная попытка, нужно фиксировать причину неудачи)
- список активных сертификатов (аккаунтов)
  - со сроками действия
  - с признаком наличия CCD файла (файл присутствует - можно подключиться, отсутствует - нельзя отключиться)
- web приложение раелизующее
  - UI просмотра данных
  - REST API
    - состояние аккаунта 
	  - валиден/отозван (CRL)
	  - подключение возможно / заблокировано (CCD)
	  - ID последней сессии (включая активную)
	- информация по сессии
	  - аккаунт
	  - время подключения/отключения (при отсутствии времени отключения - сессия считается подключенной)
	  - IP с которого было произведено подключение
	  - Геолокация точки из которой произведено подключение

Условия
  - сервис размещается на том же сервере что и openvpn
  - сервис не вмешивается в работу openvpn; никакого управления, только наблюдение
  - аутентификацию для начала сделать basic, ролей нет
  - чистка журналов не входит в функционал приложения
  - openvpn
    - версия 2.5 и позже может быть обновлен
    - работает в linux (debian)
    - можно настроить как необходимо на любой формат логов
	- конфигурации аккаунтов лежат в строгой иехархии директорий clients/<prefix><account>, внутри которой есть сам сертификат
	  - prefix фиксированный в рамках приложения и идентифицирует организацию выпустившую конфиг (для избежания у пользователя коллизий конфигураций вида <username>)
	- имеется стандартный client-config-dir в котором надо проверять наличие файла <account>
	- management interface можно использовать
	- одновременных сессий не настроено - новая сессия обрывает предыдущую
	- один сертификат = один аккаунт = один человек (мы учитываем только аккаунты. принадлежность их кому либо за рамаками приложения)
	- crl хранится локально в файле по фиксированному пути (достаточно переодически перечитывать файл)
  - GeoIP
    - допустим внешний сервис
	- офлайн база не нужна
  - БД:
    - mysql
  - языки:
    - для Web приложения предпочтителен PHP+Yii2 (если есть более подходящие варианты - предложи, поясни плюсы)
	- для скриптов сбора и обработки данных предпочтительно bash/Python (если есть более подходящие варианты - предложи, поясни плюсы)
  - нагрузки на приложение считаем незначительными
