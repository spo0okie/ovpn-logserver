# План устранения недочётов

Источник — [docs/known-gaps.md](../docs/known-gaps.md). Порядок: от простого к
сложному. Тема неудачных попыток подключения сюда не входит: каркас удалён,
проработка вынесена в [docs/connection-attempts.md](../docs/connection-attempts.md). Внутри этапа пункты независимы, между этапами — нарастает риск и объём.

**Прод живой**, поэтому у каждого пункта отмечено, затрагивает ли он работающую
систему. Правила: после каждого этапа `pytest` должен быть зелёным (сейчас
339 passed), выкатывать этапами, а не всё разом.

Оценки в человеко-часах ориентировочные, для одного разработчика в контексте.

Отдельная находка: скрипты хранились в репозитории с CRLF — на Linux такой хук

рабочее дерево и индекс нормализованы.

Проверено на живом стенде: контейнер healthy, отпечаток CA до и после
пересоздания совпадает, миграции 001–004 применились на реальном MySQL, хук
записал сессию, повторное подключение корректно закрыло старую как `error`.

### Исходный план этапа

### 3.1. Локальное время на странице сессий
`/sessions` — самая нагруженная временем страница — показывает сырой UTC. Таблица
рендерится клиентским DataTables через AJAX, серверный Jinja-фильтр к ней
неприменим (см. [docs/timezone.md](../docs/timezone.md)). Варианты:
- **(а)** `render`-функция в определении колонки DataTables, конвертирующая ISO-UTC
  в локальное время браузера. Проще, но время будет в зоне клиента, а не сервера —
  это расхождение с остальными страницами.
- **(б)** отдавать из API дополнительное предформатированное поле
  (`connected_at_local`), сформированное тем же `format_datetime`. Единообразно со
  всем остальным UI.
- **Рекомендация:** (б) — консистентность важнее, зона сервера уже принята за
  канон везде.
- Добавить тесты на `web/utils/timezone.py` — сейчас их нет ни одного.

### 3.2. Атомарность закрытия orphaned и создания сессии
В `collector/client_connect.py` `create_or_get_account`, `close_orphaned_session` и
`create_session` коммитят каждый сам по себе. При сбое между шагами возможно
состояние «старая сессия закрыта, новая не создана».
- Объединить закрытие orphaned и создание новой сессии в одну транзакцию
  (account по-прежнему коммитить отдельно — он нужен обоим шагам).
- **Осторожно:** нельзя нарушить инвариант I4.5 — при любой ошибке exit 0.
- **Прод:** затрагивает горячий путь подключения. Выкатывать отдельно от других
  правок, с проверкой на стенде.
- **Проверка:** тест с искусственным сбоем между шагами — сессия либо создана,
  либо старая осталась активной; промежуточного состояния нет.

### 3.3. Починить PKI в Docker-стенде
`docker/openvpn-server/entrypoint.sh` выполняет `easyrsa init-pki` с рабочим
каталогом `/usr/share/easy-rsa`, поэтому PKI создаётся там, а не в томе
`openvpn_pki`. Проверка «PKI уже есть» смотрит в `$PKI_DIR` и всегда истинна —
**каждое пересоздание контейнера генерирует новый CA**, тогда как клиентские
сертификаты в томе остаются от старого.
- Задать `EASYRSA_PKI=$PKI_DIR` либо выполнять `init-pki` с нужным cwd.
- Заодно: CRL от easy-rsa истекает (по умолчанию 180 дней), обновления нет —
  добавить перегенерацию в тот же периодический запуск, что и 2.3.

### 3.4. Привести в порядок тесты Docker-стенда
`docker/tests/` обращаются к неопубликованному порту 3306 и к `localhost:8000`
вместо `8001`, ждут PKI по путям, которых entrypoint не создаёт, и используют
legacy-бинарь `docker-compose` (v1) — 45 вхождений по обоим каталогам тестов.
Обновить порты и пути, перевести на `docker compose` (v2). Делать **после** 3.3,
иначе часть тестов чинить не под что.

### 3.5. Разобраться с tests/e2e/test_end_to_end.py
Файл не запускается: фикстуры (`e2e_vpn_simulator`, `e2e_data_factory` и другие)
нигде не определены, а сам он не e2e — Docker не задействован, всё на SQLite.
Решить:

- либо переписать под реальный Docker-стенд,

- **Рекомендация:** удалить. Дублирует существующее покрытие и создаёт ложное
  ощущение, что e2e есть.

## Этап 4. Крупные задачи (недели, риск высокий)

### 4.1. Унификация naive/aware datetime
Сейчас: `datetime.utcnow()` (naive) почти везде, `datetime.now(timezone.utc)`
(aware) в `web/auth.py`. Сравнение naive и aware даёт `TypeError`. Дополнительно
часть колонок имеет одновременно client-side default в моделях и
`server_default CURRENT_TIMESTAMP` в миграциях — запись мимо ORM даёт время в зоне
сервера БД, через ORM — UTC.

Работа сквозная, затрагивает и collector, и web, и миграции:
1. договориться о каноне (предлагается aware-UTC — `datetime.utcnow()` объявлен
   устаревшим начиная с Python 3.12);
2. привести код к нему;
3. решить, что делать с `server_default` — либо убрать, либо признать
   единственным источником;
4. проверить сравнения дат в фильтрах API.

**Прод:** затрагивает всё. Данные в БД при этом не мигрируют — они уже в UTC.

### 4.2. Доделать UI до заявленного
Из исходного дизайна не реализовано: графики (Chart.js подключался, но не
используется — нет ни одного `<canvas>`), экспорт в CSV на `/sessions`, отдельная
страница деталей сессии `/sessions/{id}` (эндпоинт API для неё уже есть).

Делать по потребности; ценность ниже, чем у 4.1.

### 4.3. Зафиксировать версии зависимостей
Сейчас во всех трёх `requirements.txt` только нижние границы (`>=`), lock-файла
нет — любой релиз SQLAlchemy или FastAPI может молча сломать прод. Перейти на
пины с lock-файлом (`pip-tools` либо `uv`). Требует прогона тестов на
зафиксированных версиях и аккуратной выкатки.
