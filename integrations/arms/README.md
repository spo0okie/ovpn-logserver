# Интеграция с инвентаризацией ARMS

Провайдер для механизма подключаемых интеграций
[ARMS](https://github.com/spo0okie/arms_inventory) (`docs/dev/integrations.md`
в репозитории ARMS). Показывает статус VPN-клиентов OpenVPN прямо в
инвентаризации. Работает только на чтение и ничего не меняет ни в ARMS, ни в
логсервере.

Провайдер **поставляется с логсервером, а не с ARMS**. В дереве ARMS его нет:
если у инстанса ARMS нет логсервера, об интеграции там ничего не знают.
Подключается она двумя блоками в `config/params-local.php` ARMS, код ARMS не
меняется.

## Что видно в ARMS

Привязка — по **имени IP-записи**. Provision заводит VPN-адрес клиента в
инвентаризации под именем `<префикс><CN>`: `ovpn-ivanov`, `ovpn2fa-ivanov`.
Префикс однозначно называет инстанс OpenVPN (`server_name` логсервера), поэтому
VPN-сети отдельно не помечаются: провайдер применим к IP, имя которого
начинается с известного префикса.

Статус пары «CN + инстанс», по убыванию приоритета:

| Статус | Когда |
|---|---|
| в сети | есть активная сессия на инстансе |
| включён | есть действующий сертификат и CCD на инстансе — может подключиться |
| выключен | сертификат действует, CCD на инстансе нет |
| отозван / истёк | действующих сертификатов нет |
| нет в VPN | сертификатов с таким CN в логсервере нет |

Где это показано:

- **иконка у IP** — везде, где адрес рисуется элементом (карточки ОС,
  оборудования, сотрудника). Цветной кружок статуса; у «в сети» рядом тикающее
  время сессии. Подробности — в подсказке и в карточке IP (клик по адресу);
- **колонки «Статус OpenVPN» и «Источник»** — в таблице адресов карточки сети
  (появляются, если хотя бы один адрес сети — VPN-клиент) и в списке IP
  (включаются персонализацией грида). Источник у «в сети» — текущий адрес
  подключения и геометка; у остальных — последнее подключение на этом
  инстансе, приглушённо и с датой;
- **панель в карточке IP** — статус, источник, инстанс, срок сертификата и
  ссылка в веб-интерфейс логсервера.

Каждая страница ARMS — **один** запрос `POST /api/v1/integrations/status`
(контракт — [docs/api.md](../../docs/api.md#статус-для-интеграций)). ARMS
кэширует ответы (панель — по `cacheTtl`, колонки и иконки — по `cellTtl`, не
меньше 15 сек) и никогда не ждёт логсервер при рендере страницы.

## Подключение

1. Код провайдера должен быть доступен процессу PHP ARMS. На одном хосте —
   это каталог логсервера, например `/opt/openvpn-logserver/integrations/arms`.
   Если ARMS в Docker, смонтируйте каталог в контейнер, например
   `- /opt/openvpn-logserver/integrations/arms:/opt/arms-openvpn:ro`, и
   используйте путь внутри контейнера. Нужен только каталог
   `integrations/arms`, остальной логсервер ARMS не нужен.

2. Заведите в логсервере отдельного пользователя для ARMS. Добавьте его в
   список `auth.web.users` в `config/auth.yaml` и перезапустите web
   (`systemctl restart openvpn-web`):

   ```yaml
   auth:
     web:
       username: admin                   # основной пользователь - как был
       password_hash: "$2b$12$..."
       users:
         - username: arms
           password_hash: "$2b$12$..."   # bcrypt-хеш пароля для ARMS
   ```

   Хеш генерируется командой
   `python3 -c "import bcrypt; print(bcrypt.hashpw(b'ПАРОЛЬ', bcrypt.gensalt()).decode())"`.
   Сам пароль, не хеш, указывается в конфиге интеграции в ARMS (п.3). Чтобы
   отозвать доступ ARMS, уберите пользователя из списка и перезапустите web.
   Подробнее — [config/README.md](../../config/README.md#authyaml--вход-в-веб-интерфейс).
   Логсервер должен быть доступен **с сервера ARMS**; браузеру пользователя —
   только если нужна ссылка «Открыть в OpenVPN LogServer».

3. В `config/params-local.php` ARMS:

   ```php
   <?php
   require_once '/opt/openvpn-logserver/integrations/arms/autoload.php';

   return [
       // ...
       'integrations' => [
           'openvpn' => [
               'class' => \openvpnlogserver\arms\OpenVpnProvider::class,
               'url' => 'http://vpnlog.local:8000',   // адрес API, достижимый С СЕРВЕРА ARMS
               'user' => 'arms',                      // пользователь логсервера из п.2
               'password' => '...',                   // его пароль (не хеш)
               // префикс имени IP-записи => server_name инстанса логсервера
               // (null - любой инстанс). По умолчанию - соглашение provision
               // для одиночного инстанса:
               //'prefixes' => ['ovpn-' => 'local', 'ovpn2fa-' => 'local-2fa'],
               //'web' => 'https://vpnlog.corp',       // адрес для браузера, если отличается от url
               //'title' => 'OpenVPN',
               //'expiringDays' => 30,                 // предупреждать о сертификате, истекающем раньше
               //'cacheTtl' => 0,                      // панель IP: 0 - обновлять при каждом открытии
               //'cellTtl' => 30,                      // колонки и иконки, сек (не меньше 15)
               //'timeout' => 5,
               //'verifySsl' => true,                  // false - самоподписанный сертификат логсервера
           ],
       ],
   ];
   ```

   `autoload.php` регистрирует только загрузчик пространства имён
   `openvpnlogserver\arms\`. Классы грузятся лениво, когда приложение уже
   поднято, поэтому `require_once` в начале `params-local.php` безопасен.

4. При `useRBAC` права на просмотр создаёт `php yii rbac/init`
   (`view-integration-openvpn`). Пользователям с глобальным `view` ничего
   выдавать не нужно.

Если логсервер недоступен или отвечает 401, в ячейках появится «недоступно».
Причина пишется в лог ARMS, а в debug-режиме видна прямо в ячейке. Прошлый
кэш при этом не затирается.

Мультисайт: на каждый инстанс свой префикс, например
`'prefixes' => ['ovpn-' => 'chl', 'ovpn2fa-' => 'chl-2fa', 'msk-ovpn-' => 'msk']`.
Имена инстансов — те же, что `openvpn.server_name` на серверах
([multisite.md](../../docs/multisite.md)); список виден в `GET /api/v1/servers`.

## Требования к ARMS

Нужна версия ARMS, в ядре интеграций которой есть бейджи у элементов
(`IntegrationProvider::itemBadges()`) и колонки ручных таблиц
(`IntegrationsRegistry::tableColumns()`). На более старой ARMS провайдер не
сломается, но будет работать неполностью: не появятся иконки у IP и колонки в
карточке сети. Панель IP и колонки списка IP будут работать.

## Тесты

Тест провайдера написан для юнит-набора ARMS (Codeception) и выполняется в
окружении ARMS. В дерево ARMS его не коммитят — копируют на время прогона:

```sh
cd /path/to/arms
mkdir -p tests/unit/external
cp /opt/openvpn-logserver/integrations/arms/tests/OpenVpnProviderTest.php tests/unit/external/
LOGSERVER_ARMS_DIR=/opt/openvpn-logserver/integrations/arms php vendor/bin/codecept run unit external/
rm -rf tests/unit/external
```

Сеть в тесте не используется: транспорт `httpPost()` подменяется наследником.
Серверная сторона (эндпоинт статуса) покрыта тестами логсервера:
`pytest web/tests/test_integrations.py`.

## Состав

| Файл | Назначение |
|---|---|
| `autoload.php` | загрузчик пространства имён `openvpnlogserver\arms\` |
| `src/OpenVpnProvider.php` | провайдер: привязка, батч-запрос, рендер иконки/колонок |
| `views/panel.php` | панель в карточке IP |
| `tests/OpenVpnProviderTest.php` | юнит-тест для прогона в окружении ARMS |
