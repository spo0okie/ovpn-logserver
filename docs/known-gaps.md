# Незакрытые места

Список того, что заявлено, но не работает или сделано наполовину. Ведётся, чтобы
это не приходилось выяснять заново по коду.

## Функциональность

**Неудачные попытки подключения не собираются** и каркас для них удалён.
Причины и возможный подход — [connection-attempts.md](connection-attempts.md).

**Страница `/sessions` показывает время в UTC.** Таблица в
`web/templates/sessions.html` рендерится клиентским DataTables через AJAX, и
серверный Jinja-фильтр `local_datetime` к ней неприменим. Подробности —
[timezone.md](timezone.md).

**Не смешаны, но и не унифицированы naive/aware datetime.** Часть колонок имеет
одновременно client-side default в моделях и `server_default CURRENT_TIMESTAMP` в
миграциях: запись мимо ORM даёт время в зоне сервера БД, через ORM — UTC.

**Нет графиков.** Chart.js заявлялся в исходном дизайне, но не подключён: на
дашборде только карточки с метриками. Нет также экспорта в CSV на `/sessions` и
отдельной страницы деталей сессии `/sessions/{id}` (в API такой эндпоинт есть).

## Надёжность

**Закрытие orphaned-сессии и создание новой в `client_connect` — не одна
транзакция.** `create_or_get_account`, `close_orphaned_session` и `create_session`
коммитят каждый сам по себе: при сбое между ними возможно состояние «старая сессия
закрыта, новая не создана».

**Нет защиты от параллельного запуска `sync_all`** (ручной запуск поверх
systemd-таймера) — file-lock отсутствует.

**Остаточная гонка `session_cleanup` × `client_connect`**: `snapshot_time` закрывает
основное окно, но `connected_at` берётся из `time_unix` — времени начала
подключения, а не вставки строки. Окно равно длительности TLS-handshake.

## Тесты и инфраструктура

- `tests/e2e/test_end_to_end.py` не запускается: фикстуры (`e2e_vpn_simulator`
  и другие) нигде не определены. Кроме того, это не e2e — Docker не задействован.
- `tests/e2e/test_session_cleanup_e2e.py::test_e6_6` противоречит инварианту C1.7
  (fail-closed): создаёт активную сессию без реальных VPN-клиентов и ждёт, что
  cleanup пометит её `error`. Плюс хардкод MySQL-кредов мимо `${MYSQL_USER}`.
- `database/tests/test_schema.py::TestInvariantI11` проверяет удалённый инвариант
  `uk_cn` (уникальность по одному `cn`) — на актуальной схеме провалится.
  Локально маскируется отсутствием MySQL.
- `docker/tests/` устарели: обращаются к неопубликованному порту 3306 и к
  `localhost:8000` вместо `8001`, ждут PKI по путям, которых entrypoint не создаёт,
  используют legacy-бинарь `docker-compose` (v1).
- CI отсутствует полностью.

Эти наборы исключены из сборки по умолчанию через `pytest.ini`; запускать явно.

## Docker-стенд

- `entrypoint.sh` openvpn-сервера генерирует PKI в `/usr/share/easy-rsa/pki`, а не
  в томе `openvpn_pki` — при пересоздании контейнера появляется новый CA, тогда
  как клиентские сертификаты в томе остаются от старого.
- CRL, сгенерированный easy-rsa, истекает (по умолчанию 180 дней); обновления нет.
- `sync_all.py` в стенде не запускается по расписанию — только вручную через
  `docker exec`.
